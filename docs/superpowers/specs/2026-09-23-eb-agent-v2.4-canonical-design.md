# EB Agent v2.4 — Canonical Single Source of Truth

**Instruction:** `AGENT_ThamDinh_INSTRUCTION_FINAL.md` (v2.4, "MỘT NGUỒN SỰ THẬT + CHẶN LỆCH DỮ LIỆU"), uploaded 2026-09-23.

## Context

This session already implements v2.3 in full (H1–H9 display contract, the 3-column
M1–M7/R1–R2/L1–L2 layout, S7.1–S7.5 except verdict (f), S8, Stress Test, and the
Soạn/Xuất tờ trình MB02a module) and, earlier in this same session, root-caused and
fixed the exact production incident this v2.4 revision formalizes: a single upload
bundling a BCTC sheet with an unrelated bank-statement ("sao kê") sheet caused the
report year to be misdetected from the statement's transaction dates instead of the
BCTC's own year, and caused the mandatory-document classifier to miss the BCTC
entirely. Those two fixes are shipped and verified live.

What v2.4 formalizes beyond those point fixes is architectural: **the codebase
currently has two independent extraction pipelines for the same BCTC fields** —
`financial_inputs.py`'s period-aware extraction (feeds `credit_engine`/ratios) and
each `overview/*.py` condition evaluator's own independent regex search via
`find_all_matches` (feeds the condition table). They can disagree, because they are
two different code paths reading the same source text with separately-maintained
patterns. The instruction requires this collapsed into one canonical layer that both
read from, plus three new Bước 0 checks (`sheet_scan`, `cột năm`, `consistency`) and
a new hard-block verdict when the (now theoretically impossible, but still checked
defensively) disagreement is detected.

## Goal

1. Every BCTC-numeric value shown anywhere in the EB screen or the MB02a export comes
   from exactly one extraction pass (`canonical`), never a second independent regex
   search over the same documents.
2. The report year is determined only from sheets identified as BCTC content, scanning
   every sheet in the upload to make that identification — never from an unrelated
   sheet's own dates (already fixed this session for the primary-year path; this spec
   extends the same discipline to sheet identification itself).
3. A genuine cross-check still runs before every response, and if it ever finds two
   different values for the same canonical field, the response says so plainly and
   blocks the tờ trình export — hard, no override — rather than silently picking one.

## Non-goals

- Migrating `overview` conditions that read non-BCTC-financial fields (industry,
  legal status, operating history, CIC, partner/counterparty data) — they already
  read from genuinely different sources than `financial_inputs`, so there is no
  duplicate-pipeline risk to eliminate for them.
- `evaluate_revenue_6m_statement` (bank-statement-derived revenue check) — it
  deliberately reads the *sao kê*, not the BCTC; folding it into `canonical` would
  conflate the two source types this whole incident was about keeping apart.
- Re-deriving `CALC_*` ratio/metric values through `canonical` — those already flow
  from a single set of `compute_*` functions consuming `EbFinancialInputs`
  (`app/agents/eb/*.py`), which itself will now be *built from* canonical. That
  computation layer was never duplicated and needs no change.

## Architecture

### New module: `app/agents/eb/canonical.py`

```python
@dataclass
class CanonicalField:
    ma: str                              # e.g. "BS_EQUITY" — internal only, never rendered (H2)
    nhan: str                            # Vietnamese label
    gia_tri: float | None
    don_vi: str                          # "VND" | "lần" | "%" | "ngày" | "tỷ lệ"
    nam: str | None
    nguon: str | None                    # source/fallback description
    sheet: str | None                    # which sheet this was read from
    loai: str                            # "trich_xuat" | "fallback" | "uoc_tinh" | "tinh_toan" | "chua_co"
    co_gia_tri: bool
    evidence: list[EvidenceRef]

@dataclass
class SheetScanResult:
    sheet: str
    included: bool
    reason: str                          # why included/excluded, always shown (Bước 0)

@dataclass
class ConsistencyResult:
    khop: bool
    danh_sach_lech: list[dict]           # [{"chi_tieu": ..., "gia_tri_1": ..., "gia_tri_2": ...}]

@dataclass
class CanonicalResult:
    fields_by_year: dict[str, dict[str, CanonicalField]]   # year -> {ma: CanonicalField}
    sheet_scan: list[SheetScanResult]
    consistency: ConsistencyResult

def build_canonical(documents: list[ExtractedDocument]) -> CanonicalResult: ...
```

`build_canonical` is the **only** place in the codebase allowed to run a BCTC-field
regex search (`_FIELD_PATTERNS` from `financial_inputs.py`, reused not duplicated)
against extracted tables. Every other module — `financial_inputs.py`,
`overview/equity_profit.py`, `overview/revenue.py`'s `evaluate_revenue_12m` — is
rewritten to look values up in `CanonicalField`s already built, never to call
`find_all_matches`/`find_all_matches_by_period` on `_FIELD_PATTERNS` itself again.

### Sheet scan (Bước 0 — `sheet_scan`)

Reuses the multi-label pattern already built this session
(`app/agents/rb/document_classifier.classify_document_types`, the whole-document
version) at the **table/sheet granularity**:

```python
def classify_sheet(table: ExtractedTable) -> tuple[bool, str]:
    """(included, reason) — every sheet in every document is scanned; a sheet is
    included in canonical extraction if its own name matches a known BCTC-sheet
    naming pattern (CDKT/KQKD/LCTT/BCTC/TOM_TAT/CAN_DOI...) OR its own content
    clears a keyword-density threshold against the FINANCIAL_STATEMENT keyword
    set — same confidence math as classify_document_types, scoped to this one
    table's own rows instead of the whole document's text."""
```

`build_canonical` calls this for **every table in every document** (the instruction's
explicit ask: "scan toàn bộ các sheet"), and only feeds included sheets' rows into the
per-field extraction. Excluded sheets are never silently dropped — every one is
listed in `sheet_scan` with its reason, satisfying Bước 0's "luôn hiển thị sheet nào
đã quét, sheet nào bỏ qua và LÝ DO." A sheet whose own name is ambiguous but whose
content clears the threshold is included (content wins over an inconclusive name);
a `sheets=all` request bypasses exclusion entirely (every sheet included, still
reported).

### Year resolution (Bước 0 — `cột năm` / `nam_bao_cao`)

Already substantially built this session: `detect_table_primary_year` (scoped to one
table) and `detect_year_columns` are reused unchanged — they are exactly the "never
let another sheet's dates leak in" primitives this spec needs, now explicitly only
ever invoked on sheets `sheet_scan` included. `router.py`'s `select_richest_period`
(added this session) remains the auto-selection heuristic when the user hasn't picked
a year. New: the response surfaces `cac_nam_co_trong_ho_so` (all years found across
included sheets) and `nam_can_nguoi_dung_xac_nhan` (true when more than one candidate
year exists and none was explicitly requested), which the frontend uses to cap
Confidence at M per the instruction — Confidence itself is a new small computed field
(H/M based on coverage ≥90%/70-90%, capped at M when year confirmation is pending).

### Consistency check (Bước 0C / S7.2(f))

Because every canonical-numeric consumer now reads the *same* `CanonicalField`, two
blocks can no longer independently disagree by construction — the T32 failure mode
(BCTC block reads `BS_EQUITY`, condition block reads legacy `BS008`, they diverge) is
closed at the architecture level, not papered over with a runtime comparison. The
`consistency.khop` signal that remains is a genuine defensive check for the case a
single canonical field itself has **conflicting raw matches** — e.g. two different
BCTC-included sheets in the same upload both contain a "Vốn chủ sở hữu" row with
different numbers. `build_canonical` already computes this per-field (the existing
period-aware extraction's `len(distinct_values) > 1` branch, reused, not duplicated)
and folds every such conflict into `ConsistencyResult.danh_sach_lech`. The existing
Bước 0 balance check (`sanity_checks.balance_mismatch`, already shipped) is included
as one more entry in the same list when it fires, since it is the same class of
finding ("hai con số không khớp cho cùng một chỉ tiêu").

`router.py` folds `not consistency.khop` into `pre_check_blocked` — the exact same
mechanism `balance_mismatch` already uses (added this session), which already
produces `block_type="HARD"` and, per this session's earlier fix, is already
never bypassable by `force`. The only genuinely new pieces are:
- A `loai_chan` field on the gate result (`"LECH_DU_LIEU"` vs the existing generic
  hard-block reason) so the frontend can render S7.2-bis's specific copy and swap
  the usual "Xem chi tiết tín hiệu rủi ro" / "Vẫn xuất bản nháp" button pair for a
  single **"Chạy lại trích xuất"** button (S7.2-bis: no override button exists for
  this case at all).
- The S7.2-bis-mandated wording ("Hệ thống đọc ra hai kết quả khác nhau cho cùng một
  chỉ tiêu nên tạm dừng xuất tờ trình...") replacing the generic unreadable-upload
  message when `loai_chan == "LECH_DU_LIEU"`.

### Legacy alias resolution

`FIELD_CODE_MAP` (already shipped, `app/agents/eb/field_codes.py`) plus a small new
`LEGACY_ALIAS: dict[str, str]` (`{"BS008": "BS_EQUITY", "BS003": "BS_AR_CUSTOMER",
"BS004": "BS_INVENTORY", "BS005": "BS_AP_SUPPLIER", "DEBT_LT_PRINCIPAL_DUE":
"DEBT_PRINCIPAL_DUE"}`) resolves at the one place canonical field codes are looked
up — a legacy code is never a live key in `CanonicalResult.fields_by_year`, it only
ever redirects to the current one, matching H4's "cấm dùng song song hai hệ mã."

### Migration scope (call sites rewritten to consume canonical, not re-extract)

| File | Current | New |
|---|---|---|
| `financial_inputs.py::extract_period_aware_financial_inputs` | independently runs `find_all_matches_by_period` per `_FIELD_PATTERNS` entry | built by copying `canonical.fields_by_year[year][ma].gia_tri` into the matching `EbFinancialInputs` attribute via `FIELD_CODE_MAP` |
| `overview/equity_profit.py::evaluate_equity` | own `_EQUITY_PATTERN` + `find_all_matches` | reads `canonical["BS_EQUITY"]` for the selected year |
| `overview/equity_profit.py::evaluate_lnst_pakd`, `evaluate_gross_profit_less_interest` | own patterns | same — canonical lookup (`gross_profit_less_interest` needs a `IS_GROSS_PROFIT` canonical entry added to the field map; today it isn't extracted anywhere, so this closes a real gap) |
| `overview/revenue.py::evaluate_revenue_12m` | own `_REVENUE_PATTERN` | reads `canonical["IS_REVENUE"]`; its own 12-month min/max policy comparison is unchanged, only the *source* of the number changes |
| `router.py` | calls `extract_period_aware_financial_inputs` + `evaluate_overview` independently | calls `build_canonical` once, passes the result into both |

Everything downstream of `EbFinancialInputs` (all `compute_*` metric functions, all
`evaluate_rfNN_*` red flags, `sanity_checks.py`, `export_gate.py`, `mb02_export.py`)
is unchanged — they already consume `EbFinancialInputs`/`FieldEvidence`, not raw
documents, so `canonical` slots in underneath them without touching their own logic.

## Review Focus (uncovered-by-plan risk, named up front for the plan/reviewer)

1. **`gross_profit_less_interest`'s `IS_GROSS_PROFIT` has no existing extraction
   pattern anywhere in the codebase today** — this migration is the first time it's
   defined. Get the KQKD label/mã right (likely mã 20, "Lợi nhuận gộp về bán hàng và
   cung cấp dịch vụ") or the condition regresses from "sometimes finds it via ad hoc
   regex" to "never finds it."
2. **`sheet_scan`'s keyword-density threshold for xlsx sheets with sparse/unusual
   labeling** (real BCTC "tóm tắt" sheets are often mostly numbers with few keyword
   hits) — a threshold tuned only against the Alpha Group fixture risks excluding a
   real customer's valid BCTC sheet that happens to use terser labels. Test against
   at least one deliberately minimal-label fixture, not just the rich Alpha Group one.
3. **Multiple BCTC-shaped sheets in one upload that are legitimately NOT conflicting**
   (e.g. current-year and comparative-year BCTC on separate sheets, or a
   parent-company vs consolidated BCTC) — `consistency.khop` must not fire on two
   sheets that both correctly describe *different* years or *different* legal
   entities. Scope the conflict check to same-year, same-field comparisons only.
4. **`revenue_12m`'s policy window is 12 trailing months, not a fiscal year** — once
   it reads `canonical["IS_REVENUE"]` (an annual BCTC figure), confirm this doesn't
   silently change `evaluate_revenue_12m`'s actual semantics from what it compares
   today; if the two were never really the same number, migrating it is a Non-goal,
   not a Goal, and this line item should be dropped from the plan instead of forced.
5. **`build_canonical` must still run when zero sheets pass `sheet_scan`'s inclusion
   test** (e.g. an upload that's ONLY a bank statement, no BCTC at all) — confirm the
   existing Bước 0 "unreadable/unclassified" hard-block path still fires correctly
   through the new layer rather than `canonical` silently returning an empty-but-
   successful result that later code mistakes for "extracted, just all missing."
