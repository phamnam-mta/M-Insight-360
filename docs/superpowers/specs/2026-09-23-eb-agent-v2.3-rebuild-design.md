# EB Agent v2.3 Rebuild — Design Spec

## Context and goal

The EB (Enterprise / KHDN) credit-assessment agent is being rebuilt against
a new, extremely prescriptive instruction: `AGENT_ThamDinh_INSTRUCTION_FINAL`
v2.3 (Vietnamese, 941 lines), now copied into this repo at
`docs/instructions/AGENT_ThamDinh_INSTRUCTION_FINAL_v2.3.md`. That file is
the **binding source of truth** for every threshold, field code, UI slot,
copy string, and export rule below — this spec organizes the work and
records the decisions needed to implement it against *this* codebase; it
does not restate the instruction's content in full. Task briefs written
from this spec's plan must cite the instruction's own section IDs (H1–H9,
S0–S8, T1–T28) rather than paraphrasing them.

Three things the user asked for, in one pass:
1. Rebuild the EB Agent's business logic and 3-column result screen to
   conform to v2.3 — most importantly its **9 Hard UI Laws (H1–H9)**, the
   **S7 Export Gate**, and the **complete removal of the cross-sell module**
   from the EB screen (v2.3 explicitly reverses the prior spec's decision to
   keep a lightweight cross-sell adapter inside EB — that now belongs
   entirely to the separate Cross-sell Agent).
2. Replace the from-scratch `.docx` export in `mb02_export.py` with one that
   fills the **real** MB02a/QT.RR.037 bank template, now copied into this
   repo at `docs/templates/template_MB02a.docx` (55 tables), by label-match
   (H4/S2), not by hard-coded table/cell coordinates.
3. *(Already delivered separately, out of scope here — see "Already done"
   below.)* Show a sample assessment under "Thẩm định Khách hàng mới" when
   the user has no history yet.

**Scope classification:** architectural (new export pipeline, a new S7 gate
subsystem, and a full UI-layout rewrite against a fixed slot contract — not
a bounded change to code that already implements this flow). One spec, one
plan, covering all of groups A–D below, per the user's explicit choice
("1 spec + 1 plan lớn cho toàn bộ").

(verbatim copy of the user's `demo.html`) shown in an iframe under the EB

## What already exists vs. what v2.3 actually requires

A prior spec (`2026-09-22-eb-screen-redesign-stress-test-design.md`) already
built a substantial amount of this system: period-aware BCTC extraction,
NWC/current-ratio/DSCR/ICR/leverage metrics, capital-balance-check, QĐ 039
receivables financing, a 7-rule red-flag engine (RF01–RF07), and a full
Stress Test v2 module (scenarios, persistence, conclusions, drawer UI). Do
**not** rebuild these from scratch. This plan's real job is narrower than
"build an EB agent" — it is: **close the gap between what v2.3 mandates and
what's already there**, verified directly against the current code (not
assumed from the instruction's own framing):

| Area | Already conforms | Must change |

a backend-only change.

## Global constraints

Copied verbatim or by direct reference from the instruction (§ citations
point into `docs/instructions/AGENT_ThamDinh_INSTRUCTION_FINAL_v2.3.md`):

- **Never fabricate.** Only figures extracted from the uploaded BCTC; no
  industry averages, no model-memory numbers (Nguyên tắc sắc #1).
- **Empty ≠ zero.** A blank cell is "unreadable", never `0`, in any formula
  (Nguyên tắc sắc #3, S1.1).
- **H1–H9 are the highest-priority contract for the result screen.** Every
  KPI card, every slot, renders always — never `display:none`; unknown data
  becomes a compact `unknown` card (H1, H8), never an absent one.
- **H4: one field-code system.** New fields go into the map table before
  code uses them; no parallel ad-hoc codes.
- **H7: never borrow another period's number.** Selecting a kỳ báo cáo
  switches everything to that year; a field missing in the selected year
  shows `unknown` with the year named, even if another year has it.
- **S1.2: unit conversion in the export.** Internal values are VND; MB02a
  cells are triệu đồng (÷ 1,000,000). Screen display stays tỷ VND (÷
  1,000,000,000), 1 decimal.
- **S1.3: never auto-tick a legal/compliance checkbox.** Human judgment
  only; agent leaves them blank and lists them under
  `[VIỆC RM CẦN XÁC NHẬN]`.
- **S7: the agent cannot refuse credit, only decline to auto-export a
  draft** — and even that refusal must always be overridable by a human via
  the force button (S7.4). Insufficient data is never grounds to block
  export (S7.1's hard rule) — only credit signals (Nhóm A) or document/legal
  defects (S7.2 a/b) can.
- **Every AI-derived conclusion carries** the label "Khuyến nghị sơ bộ từ dữ
  liệu BCTC — cần phê duyệt theo quy trình tín dụng MSB."
- **No cross-sell content anywhere in the EB screen, export, or Output
  format** — not under any renamed heading ("Gợi ý sản phẩm", "Cơ hội kinh
  doanh", etc.). QĐ 039 stays (it's a credit metric, not a sales pitch) but
  must use assessment language, never sales language (banned/required
  phrase table in the instruction's "KHỐI TÀI TRỢ CHUỖI" section).
- **H2: never leak technical/system language** (`NaN`, `null`, `timeout`,
  `token`, raw field codes) to the screen or the export; format-layer
  responsibility, not calc-layer.
- MSB visual language preserved (orange CTA, green/amber/red/gray signal
  colors); demo/sample data always labeled "Demo".

## Decisions this spec locks in (so the plan doesn't re-litigate them)

### D1 — Field-code canonicalization satisfies H4 without a full rename

The instruction's canonical codes (`IS_REVENUE`, `BS_EQUITY`, `CALC_DSCR`,
...) do not need to replace every internal Python attribute name
(`net_revenue_vnd`, `equity_vnd`, ...) — a full rename touches every module
in the "already conforms" column above for no behavioral gain and risks
breaking the working Stress Test/QĐ 039 code. **Ruling:** introduce one
explicit map, `app/agents/eb/field_codes.py`, `FIELD_CODE_MAP: dict[str,
str]` from instruction code → existing dataclass attribute (e.g.
`"IS_REVENUE": "net_revenue_vnd"`), covering every ★ and non-★ row in the
instruction's field-map table. Every place that needs to *speak* the
instruction's vocabulary — the S2 export mapping (Group C), UI field-code
tooltips (L2 table, H4-required), the L2-bis sanity checks, and the S7 gate
— goes through this map, never invents its own string. This is "one system"
in the sense H4 requires: a single authoritative table, not two parallel
vocabularies used ad hoc in different files. New fields the instruction
needs that don't exist yet (see D2) get added to `EbFinancialInputs` first,
then to this map — never used bare.

### D2 — New fields `EbFinancialInputs` is missing

Cross-checking the instruction's field-map table against the current
`EbFinancialInputs` dataclass (`app/agents/eb/financial_inputs.py`), these
are referenced by S2/formulas but have no dataclass field or extraction
pattern today: `BS_TOTAL_ASSETS` (mã 270, needed for S2.2 "Tổng tài sản" and
the current-ratio... — actually derivable from
`current_assets_vnd + non_current_assets_vnd`, so add as a **computed**
property, not an extracted field, matching the instruction's own fallback
chain `Tổng TS (270) → BS_CURRENT_ASSETS + BS_NON_CURRENT_ASSETS`), and
`BS_CHARTER_CAPITAL` (mã 411, "Vốn điều lệ" — extracted field, currently
absent, needed for S2.1). `IS_COGS` (mã 11, "Giá vốn hàng bán") is also
absent and needed for `DPO` — add as an extracted field. The plan's Group A
task for this must add the dataclass fields + `_FIELD_PATTERNS` regex entry
for each, following the existing pattern in
`extract_financial_inputs`/`extract_period_aware_financial_inputs`.

### D3 — Red-flag canonicalization: Nhóm A is a closed, named set

The instruction's Nhóm A list (§ CẢNH BÁO RỦI RO) has 7 bullets, but two are
mathematically the same condition — "Vốn lưu động ròng âm" and "Nợ ngắn hạn
lớn hơn tài sản ngắn hạn" are both `current_liabilities > current_assets`.
**Ruling:** treat these as one flag (the existing `RF01` "Mất cân đối vốn"
already covers it); do not double-count. The canonical Nhóm A set the S7
gate counts against is exactly six checks, each backed by an existing or
new rule function:

| Canonical check | Rule ID | Status today |
|---|---|---|
| DSCR < 1.0x | `RF05` (repayment_capacity.py) — currently bundles DSCR+ICR into one "khả năng trả nợ yếu" flag | **split** into DSCR-only and ICR-only flags (S7.3 must list each signal separately with its own real number, per the instruction's format `DSCR 0,62x < 1,0x` · `ICR 0,75x < 1,5x` as two lines) |
| ICR < 1.5x | new `RF05B` (or renumber) | split out of `RF05` as above |
| NWC âm (⟺ nợ ngắn hạn > tài sản ngắn hạn) | `RF01` (liquidity.py) | ✅ reuse as-is |
| Tổng nợ vay / VCSH > 2.0x | **new** `RF08` (leverage.py) | does not exist — existing `RF03` computes a *different* ratio (short-term debt / something) not `CALC_LEVERAGE`; add `RF08` fresh, do not repurpose `RF03` |
| Chi phí lãi vay lớn bất thường so với EBIT | `RF07` (repayment_capacity.py) | ✅ reuse as-is |
| (Phải thu + tồn kho) / TSNH > 70% | `RF06` (leverage.py) | ✅ reuse as-is |

Two existing flags fall **outside** the instruction's canonical list:
`RF02` (CFO âm) and the current `RF03` (short-term-debt ratio, distinct
from leverage). **Ruling:** keep both, but they never enter the S7 signal
count and never render in the M6 (Nhóm A) slot — render them in **M7
(Nhóm B)** is wrong too (they're not data-completeness warnings, they're
real credit observations the instruction just doesn't happen to name).
Correct placement: **fold them into M6's rendering as informational items
visually subordinate to the six canonical ones** (same red/amber icon
family, since they *are* credit signals — H page never said Nhóm A is
closed to exactly seven items, only that whatever is counted toward S7 must
be named and real) **but explicitly excluded from both the S7 gate's
signal count and the S7.3 "N tín hiệu" listing**, with a one-line comment
in the rule-evaluation code stating why. This preserves both instruction
literalism (S7 gate math matches T19's expected `5` exactly) and the
existing rules' value (nothing silently deleted). Confirm this ruling
against T19 in Group D: the fixture must activate exactly the six canonical
rules and *not* `RF02`/`RF03`, or the ruling is wrong and needs revisiting
during plan execution.

### D4 — S2.4 (QĐ.EB.039 in the real template) is resolved: paragraph fill, not table-cell fill

Direct inspection of `docs/templates/template_MB02a.docx` (body-element
walker interleaving `w:tbl`/`w:p` in document order, same technique used
for the MB01A RB Portal export) confirmed table indices for S2.1/S2.2/
S2.3/S2.5: **table 2** = S2.1 "THÔNG TIN KHÁCH HÀNG", **table 31** = S2.2
"Các chỉ tiêu tài chính tổng quát" (14 rows, exact match), **table 32** =
S2.3 "Các chỉ tiêu khả năng đảm bảo vốn kinh doanh" (6 rows, exact match),
**table 37** = S2.5 "Kế hoạch kinh doanh" (20 rows, exact match). Table 18
was investigated and ruled out for S2.4 — it's the NCLQ (related-party)
table; its "Doanh thu" column is a related party's revenue, not the
customer's own.

**S2.4 itself has no clean numeric table anywhere in the real template —
confirmed, not assumed.** The template's "Trường hợp tài trợ đầu ra theo
QĐ.EB.039 (nếu có)" section (it appears twice — once in the proposal body,
once in the approval-evaluation body) is entirely **narrative paragraphs
with `…` placeholders**, e.g. "Hạn mức tài trợ theo phương án đầu ra dự
kiến: …" and "Hạn mức tài trợ theo dòng tiền trực tiếp đích danh: …",
followed by condition-checklist tables whose columns are `Tiêu chí |
Điều kiện | Cơ sở đánh giá | Ý kiến đánh giá`, the last column being exactly
an `Đáp ứng / Không đáp ứng` checkbox pair. **Ruling:** implement S2.4 as a
**paragraph-placeholder fill**, replacing the `…` after "Hạn mức tài trợ
theo phương án đầu ra dự kiến:" with the computed reference limit
(`BS_AR_CUSTOMER × 80%`, S1.2 unit-converted) plus the receivables-turnover
figure per the instruction's mandatory dual-number display — **never**
write to the `Ý kiến đánh giá` / `Đáp ứng`-`Không đáp ứng` cells, which are
S1.3-protected human judgment (this template independently confirms S1.3's
own reasoning: those checklist tables are evaluation checkboxes, not data
fields — matching, not contradicting, the instruction). The plan's Group C
task for S2.4 should locate the target paragraph by the same label-search
discipline as the table sections (search paragraph text for "Hạn mức tài
trợ theo phương án đầu ra dự kiến", not a hard-coded paragraph index), and
replace its trailing `…` in place, preserving the paragraph's existing
run formatting.

### D5 — Cross-sell removal is a deletion, not a relabel

The prior spec's decision to keep a lightweight cross-sell adapter inside
EB is explicitly reversed by v2.3 (§ NGOÀI PHẠM VI, § LỊCH SỬ SỬA 2.3). The
Cross-sell **Agent** (`app/agents/crosssell/`, its own router, its own
screen tab) is untouched — it is a separate agent the user already has.
Only the EB-embedded copy goes: `crosssell_adapter.py`'s
`evaluate_crosssell_opportunities` call in `router.py` (lines 188, 222),
the `crosssell_opportunities` field in the EB result payload, and the
`<CrossSellOpportunities>` block in `EbResultPanel.tsx` (lines 23, 331–334).
Do not delete `crosssell_adapter.py` itself or `CrossSellOpportunities.tsx`
— both may still be used by `CrossSellPanel.tsx` / the separate Cross-sell
tab; verify that before removing any shared file, don't just delete by
inference.

## Architecture — four work groups

### Group A — Business logic (backend)

Files: `app/agents/eb/field_codes.py` (new), `financial_inputs.py` (add
`BS_CHARTER_CAPITAL`, `IS_COGS` fields + patterns; add `BS_TOTAL_ASSETS`
computed property), `leverage.py` (add `RF08` leverage flag; keep `RF03`,
`RF06` as-is), `repayment_capacity.py` (split `RF05` into DSCR-only and
ICR-only rule results, keep `RF07`), `liquidity.py` (no change — `RF01`
already correct), a new `export_gate.py` (S7 verdict logic: three verdicts,
hard-block a/b vs soft-block c/d/e, signal counting against the D3 canonical
set, force-override handling), a new `sanity_checks.py` (L2-bis's four
checks: year-value collision, <7-digit-at-scale, single-field-in-group,
balance-sheet mismatch — returns a per-field "suspect" flag the UI and
export both honor), `router.py` (remove cross-sell call per D5; wire the
S7 gate's verdict into the assessment response; wire sanity-check results
into `financial_inputs`' evidence so downstream UI/export can flag them).

Also: a conformance pass over the existing Stress Test v2 module
(`stress_test.py`, `stress_conclusions.py`) against the instruction's
Stress Test section — confirm thresholds (1.0/1.2 DSCR buffer, 1.5 ICR
buffer), confirm "ước tính" labeling on `PAT sau stress`, confirm the 3
presets' exact percentages match the instruction's table. Expect this to
be mostly a no-op given prior work already built this; any diff found is a
small, targeted fix, not a rewrite.

### Group B — Frontend UI (`EbResultPanel.tsx` and children)

This is the largest single-file change. Rewrite `EbResultPanel.tsx`'s
3-column body against the H9 fixed-slot contract:

- **Cột giữa** (render first): M1 banner (status + 1-line conclusion +
  period + coverage% + the mandatory disclaimer label) → M2 "Cần bổ sung"
  block, conditionally rendered only when coverage < 30% → M3 exactly four
  `MetricCard`s in fixed order (NWC, Liquidity Balance, DSCR, ICR), same
  height, no 2×2 reflow on desktop → M4 `CapitalBalanceDiagram` (already
  exists, keep) → M5 `Qd039Card` (already exists, keep, retone copy per
  D-none/QĐ039 language rules) → M6 Nhóm A red flags (six canonical +
  RF02/RF03 folded in per D3, red/amber icon) → M7 Nhóm B red flags (gray
  document icon, data-completeness only).
- **Cột phải**: R1 single card containing the existing `AiInsightSection`
  content plus, inside the *same* card, R1.4's action row (Stress Test /
  Soạn tờ trình MB02a / "Giải thích chỉ số" / "Phân tích sâu") — move the
  buttons currently rendered in a sibling `<div>` into this card. The
  "Soạn tờ trình MB02a" button gets the 4-state treatment from the
  instruction's table (orange-enabled / orange+amber-dot / gray-clickable
  opens S7.3 / gray-disabled) driven by the S7 verdict from Group A, never
  a bare boolean. R2: three new locked placeholder cards (Nợ thuế, Mua sắm
  công, Trinh sát dữ liệu công khai) — gray, no CTA, fixed copy from H6.
- **Cột trái**: L1 (`CompanyInfoBlock`, already exists) and L2
  (`FinancialDataTable`, already exists) get the L2-bis suspect-value
  treatment (any field Group A's `sanity_checks.py` flags renders as
  `unknown` with the "nghi ngờ sai dòng" copy, never the raw number) and an
  explicit VND-unit table header per the instruction's L2 formatting rule.
- `MetricCard.tsx`: add the H8 compact `unknown` variant (≤60% height,
  ≤50% value font-size, reason collapsed under a "Giải thích" link, not
  expanded by default) and a `<30%` coverage "dải ngang" compact mode used
  by M3 when M2 is active.
- New component: `ExportGateScreen.tsx` (or similar) for S7.3's mandatory
  4-part screen (opening line with N signals, itemized real-number list,
  action checklist, disclaimer) plus S7.4's two buttons (view detail /
  force-export), opened as a drawer/modal per the instruction (never a page
  navigation).
- Delete: the `CrossSellOpportunities` import and block from
  `EbResultPanel.tsx` (D5).

### Group C — Real MB02a export (`mb02_export.py`)

Full rewrite. Load `docs/templates/template_MB02a.docx` via `python-docx`
instead of building a document from scratch. Fill by **label search**
(H4/S2's "dò theo nhãn dòng, không bám số thứ tự bảng"), reusing the
body-element-sequence-walker technique from the earlier MB01A RB Portal
work to correlate a table to the paragraph header that precedes it, so a
future MSB template edit that shifts table indices doesn't silently
mis-fill a cell.

Implement, in order: S1.1 (blank → `[Chưa xác định từ hồ sơ tải lên]`,
never `0`, never silent) · S1.2 (÷1,000,000, Vietnamese thousand/decimal
separators, 2-decimal ratios) · S1.3 (never tick a legal checkbox — leave
template's own checkbox state untouched) · S1.4 (`fill_log.json` sidecar:
per-cell field code, value, source [primary/fallback], S7 verdict) · S2.1
(table 2) · S2.2 (table 31, 3-column N-2/N-1/N, missing prior-period column
→ placeholder, never borrow current year per H7) · S2.3 (table 32, plus
replacing the "Nhận xét, đánh giá..." paragraph with the M-Insight AI
conclusion) · S2.4 (**per D4 — paragraph-placeholder fill on "Hạn mức tài
trợ theo phương án đầu ra dự kiến: …", never the Ý kiến đánh giá checkbox
cells**) · S2.5 (table 37, only cột Năm N-1 from BCTC, never synthesize "Năm kế
hoạch") · S8 (fields never in a BCTC keep the template's own `……`
placeholder verbatim, not the `[Chưa xác định...]` string — the
distinction the instruction insists on).

Wire S7 (Group A's `export_gate.py`) as the entry gate: `KHÔNG XUẤT TỰ
ĐỘNG` without `force=True` → raise/return a structured refusal (no bytes
generated) the router turns into the S7.3 payload; with `force=True` →
generate the file with the mandatory `[BẢN NHÁP XUẤT THEO YÊU CẦU CỦA CÁN
BỘ...]` banner inserted at the top of page 1 and `fill_log.json`'s
`xuat_theo_force: true` + actor + timestamp. Filename:
`TTTD_<TenKH>_<kỳ BCTC>_<YYYYMMDD>_BANNHAP.docx` — always the `BANNHAP`
suffix (S3.6).

`router.py`'s export endpoint changes from a bare bytes-return to one that
can also return the S7.3 refusal payload (no file) and accept a `force`
flag from the frontend's S7.4 button. Follow the RB Portal MB01A precedent
for the download itself (hidden-iframe form POST, not blob+`<a download>`)
since that bug class is already known in this codebase.

### Group D — T1–T28 regression tests

Per the user's explicit choice, fixture data comes from the numbers already
printed in `demo.html` (now at `web/public/demo-eb-sample.html`) rather
than a re-derivation from a spreadsheet that was never uploaded — e.g.
"Tài sản ngắn hạn: 293.369.838.619 — Nhãn: A. TAI SAN NGAN HAN" and the
values the instruction's own T1–T21 table already states as expected
outputs for the Alpha Group fixture (§ PHỤ LỤC — BỘ TEST HỒI QUY). Build one
shared fixture module, `tests/agents/eb/fixtures/alpha_group_demo.py`,
constructing an `EbFinancialInputs` (or the raw extracted-document form, if
testing through the extraction layer) that reproduces the instruction's own
expected T1/T2/T4/T6/T7/T11/T12 values — those numbers function as an
independent check on the extraction+formula pipeline, not just the export.

Test groups, each a `tests/agents/eb/test_*.py` file:
- **Phần A (T1–T10)** — screen-level: NWC/liquidity-balance/ICR/leverage
  computed values match the instruction's expected numbers exactly; DSCR
  renders `unknown` (missing Khấu hao + Nợ gốc đến hạn) with both missing
